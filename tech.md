# Техническое задание (ТЗ)

**Проект:** сайт‑магазин на Django (динамический интерфейс, адаптивная вёрстка)  
**Дата:** 2026-03-11  
**Цель:** реализовать магазин с регистрацией/авторизацией, каталогом товаров, карточками товаров, корзиной, заказами, отзывами и ролями пользователей. Предусмотреть хранение “чека” в профиле с возможностью удаления пользователем не ранее чем через 5 дней.

---

## 1) Технологии и общие требования

### 1.1. Стек
- **Backend:** Django (Python), ORM Django, миграции.
- **База данных:** SQLite (разработка) / PostgreSQL (по желанию).
- **Frontend:**
  - базовый вариант: Django Templates + Bootstrap 5 (с небольшой кастомизацией стилей);
  - динамика: **htmx** (рекомендуется) или классический Django + немного JS.
- **Адаптивность:** корректная работа на mobile/tablet/desktop.

### 1.2. Code First / миграции / валидация
- Все сущности описываются моделями Django (аналог CodeFirst).
- Изменения схемы БД — через миграции.
- Валидация:
  - на уровне моделей (валидаторы, ограничения);
  - на уровне форм (Django forms / ModelForms);
  - на уровне представлений (проверка прав и бизнес‑логики).

### 1.3. Ограничения и допущения
- Платёжная система **не реализуется**; создаётся “муляж оплаты” (этап подтверждения заказа/оплаты без реальных тран��акций), чтобы позже можно было подключить оплату.
- Картинки товаров: на первом этапе допускаются заглушки/пути к изображениям; наполнение — вручную позже.
- HTML‑макеты страниц магазина будут добавлены пользователем; проект должен быть построен так, чтобы “натянуть” Django‑шаблоны на эти макеты.

## 2) Роли пользователей и права доступа

### 2.1. Роли
1. **Гость (Anonymous)**
2. **Пользователь (Customer)**
3. **Менеджер (Manager)** — управляет статусами заказов.
4. **Администратор (Admin/Superuser)** — полный доступ.

**Рекомендация реализации:** Django Groups + Permissions.

### 2.2. Права доступа
- **Гость:**
  - видит приветственную страницу (landing);
  - может регистрироваться/авторизоваться;
  - *(опционально)* может просматривать каталог и карточки товаров.
- **Пользователь:**
  - просматривает каталог и карточки;
  - добавляет товары в корзину;
  - оформляет заказ (муляж оплаты);
  - видит профиль, историю заказов и статусы;
  - оставляет отзыв **только если** товар был заказан и заказ в нужном статусе (например, `DELIVERED`);
  - ставит оценку **только вместе с отзывом**;
  - видит чек по заказу; может удалить чек **после 5 дней** от даты создания чека.
- **Менеджер:**
  - видит список заказов;
  - изменяет статусы заказов.
- **Администратор:**
  - управляет товарами/категориями;
  - управляет пользователями и ролями;
  - доступ к Django Admin.

## 3) Страницы сайта (site map)

### 3.1. Публичные страницы (без авторизации)
1. **Welcome / Landing** — `/`  
   - информация о магазине;  
   - в углу: “Войти / Регистрация”.
2. **Регистрация** — `/accounts/signup/`
3. **Авторизация** — `/accounts/login/`
4. **Выход** — `/accounts/logout/`
5. *(опционально)* **Каталог товаров** — `/products/`
6. *(опционально)* **Карточка товара** — `/products/<slug>/`

### 3.2. Страницы после входа
1. **Каталог / главное меню** — `/products/`
   - список товаров;
   - поиск/фильтры (минимум: поиск по названию).
2. **Карточка товара** — `/products/<slug>/`
   - описание, цена;
   - отзывы + средняя оценка;
   - “Добавить в корзину”;
   - “Оставить отзыв” доступно только при выполнении условий.
3. **Корзина** — `/cart/`
   - позиции, количество, суммы;
   - изменить количество, удалить позицию;
   - “Оформить заказ”.
4. **Checkout (муляж оплаты)** — `/checkout/`
   - подтверждение заказа;
   - выбор “способа оплаты” (заглушка);
   - создание заказа и установка начального статуса.
5. **Профиль** — `/profile/`
   - данные пользователя;
   - ссылки на корзину;
   - список заказов со статусами.
6. **Детали заказа** — `/orders/<id>/`
   - позиции заказа;
   - статус;
   - чек (просмотр/скачивание/текст);
   - “Удалить чек” — только если прошло **≥ 5 дней** с `Receipt.created_at`.

### 3.3. Менеджерские/админские страницы
1. **Панель менеджера: заказы** — `/manager/orders/`
   - список заказов;
   - изменение статуса (формой или inline через htmx).
2. **Django Admin** — `/admin/`
3. *(опционально)* **Управление ролями** — `/admin/users/roles/` (или только через `/admin/`)
   - доступ: только администратор.

## 4) Сущности (модели/таблицы) и связи

### 4.1. Пользователи
- `User` — стандартный Django User.
- `Profile` *(опционально)*:
  - `user` (OneToOne)
  - дополнительные поля (телефон, адрес и т.п.) — по необходимости.

### 4.2. Каталог
1. `Category`
   - `name`
   - `slug` (unique)
   - `is_active`
2. `Product`
   - `category` (FK, optional)
   - `name`
   - `slug` (unique)
   - `description`
   - `price` (Decimal)
   - `image` (optional)
   - `is_active`
   - `created_at`, `updated_at`
3. `ProductReview`
   - `product` (FK)
   - `author` (FK User)
   - `text`
   - `rating` (Integer 1..5) — **только при создании отзыва**
   - `created_at`
   - ограничения:
     - *(рекомендуемо)* один пользователь — один отзыв на товар (`unique_together = (product, author)`), либо разрешить несколько (по решению);
     - создание разрешено только если пользователь купил товар и заказ “завершён” (например, `DELIVERED`).

### 4.3. Корзина и заказы
1. `Cart`
   - `user` (OneToOne)
   - `updated_at`
2. `CartItem`
   - `cart` (FK)
   - `product` (FK)
   - `quantity` (min 1)
   - ограничение: `unique_together = (cart, product)`
3. `Order`
   - `user` (FK)
   - `status` (choices): `NEW`, `PAID_MOCK`, `PROCESSING`, `SHIPPED`, `DELIVERED`, `CANCELED`
   - `total_price` (Decimal) *(опционально хранить денормализованно)*
   - `created_at`, `updated_at`
4. `OrderItem`
   - `order` (FK)
   - `product` (FK)
   - `price_at_purchase` (Decimal)
   - `quantity`
5. `Receipt`
   - `order` (OneToOne)
   - `content` (Text/JSON) или `file` (optional)
   - `created_at`
   - `deleted_at` (nullable)
   - правило 5 дней: удаление пользователем возможно только если `today >= created_at + 5 days`.

## 5) Основные сценарии (use cases)

1. **Регистрация/вход**
   - регистрация → вход → доступ к функционалу.
2. **Просмотр каталога**
   - список товаров → карточка товара.
3. **Добавление в корзину**
   - из каталога/карточки товара.
4. **Оформление заказа**
   - корзина → checkout → подтверждение → заказ создан, статус `PAID_MOCK` (или `NEW` → затем “оплачено (муляж)”).
5. **Профиль/история заказов**
   - отображение заказов, статусов, чеков.
6. **Управление статусами**
   - менеджер/админ переводит статусы (например, `NEW → PROCESSING → SHIPPED → DELIVERED`).
7. **Отзывы/рейтинг**
   - отзыв + оценка доступны только после покупки и доставки.
8. **Чек**
   - создаётся при оформлении/оплате (муляж);
   - удаление пользователем — только после 5 дней.

## 6) Требования к “современному” динамическому интерфейсу

Минимальный набор:
- добавление товара в корзину без перезагрузки (htmx);
- изменение количества в корзине inline;
- добавление/подгрузка отзывов без полной перезагрузки карточки товара;
- фильтры/поиск каталога через query string и частичную перерисовку списка.

## 8) Сессии / Application / Cache / Cookies / Query string

### 8.1. Сессии
Использовать `request.session` для:
- временных данных checkout;
- запоминания настроек отображения (если не cookie).

### 8.2. Application (глобальные настройки приложения)
- `settings.py` для глобальных параметров (например `SHOP_NAME`, `SUPPORT_EMAIL`);
- контекст‑процессор для вывода общих данных в шаблонах (название магазина, меню, счётчик корзины и т.п.).

### 8.3. Cache
Кэшировать (например, на 60 секунд):
- список категорий;
- страницы каталога (если не персонализированы);
- карточки товаров (без персональных данных).

### 8.4. Cookies
Использовать cookies для:
- `view_mode=grid|list` или `theme=light|dark`;
- запоминание “баннер закрыт”.

### 8.5. Query string
Для каталога:
- `?q=...&category=...&page=...&sort=price`
